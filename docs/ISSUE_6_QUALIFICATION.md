## Supported transient event path

The actual target reports Moonraker `v0.10.0-31-gd5ee171`; exact upstream commit `d5ee17128bb88434aacdab90c2e9e990e2b64e4a` matches the observed short revision. Its `connection.send_event` endpoint is WebSocket-only and accepts only a connection identified as `type: agent`. Registration is in-memory, the event becomes `notify_agent_event` for connected clients, and the agent is removed on disconnect. A short-lived client therefore needs no service, plugin, Moonraker configuration, new credential or persistent registration when the existing trusted-LAN authorization applies.

No event has been sent to the actual target. The display adaptation uses the separate plugin ID `helix-orca-display` and event `helix_orca_display.available.v1`, with schema `helix-orca-display/v1` and required `display_only: true`. The receipt carries the original effective profile temperature separately from the prepared 230–190 °C tower range, preserving the saved/edited context distinction. It never emits the official `helixcal.*` namespace: a co-installed full Calibration Bridge could otherwise accept that event and expose its Start flow. Offline tests prove strict byte/case schema parity, nine-band file binding, request-scoped `Received · not printed · not applied` behavior, Dismiss, a total transport deadline, bounded WebSocket frames, bounded HTTP file readback, and a WebSocket RPC allowlist containing only `server.connection.identify` and `connection.send_event`.
