# Native V1 derivative

This Build Program #14 derivative keeps the accepted `orcacal` identity, native
Helix home tile, overlay/header/Back navigation and responsive token language.
It adds five calibration configuration views, a prepared-job review with separate
Confirm and Start actions, progress, bounded evaluation and original-Orca return.
It never modifies or deploys the accepted Temperature plugin or physical install.

Build with `python3 scripts/v1-native-plugin.py --output <new cache directory>`.
The builder verifies the exact accepted shell source hashes and refuses existing,
symlinked or repository destinations. Runtime output defaults to the user cache;
captures default to XDG state. Only storage is requested. No native networking,
process, print RPC or profile mutation exists. The V1 coordinator remains the
trusted verifier of generator parity, expiry and exact independent completion.
Physical Start has no action adapter in this candidate. Native Start only stores
an exact preparation-bound one-shot intent after a prior Confirm round trip.

The common `docs/V1_CONTRACT.md` v2 contract is the current path: offers provide
runtime-generated request nonce/timestamps and originating filament identity;
Prepared binds an independently qualified pinned build route plus exact artifact
and structured processing warnings; application events report the official Orca
preset transaction. The original v1 objects remain accepted only for retained
historical sessions and fixtures. Native has no supported clock/hash API and structurally
compares immutable identity, parameters, job and result; it does not claim to hash
or enforce wall-clock expiration. The coordinator owns these checks. Restart
locks all unverified actions; a retained selection stays immutable until the exact
originating receipt. No event alone authorizes a physical action.

`catalog.json` declares numeric control bounds and fixed/choice fields, checked
against shared Python limits by the builder. Ordinary zero-to-two decimal values
open beta.12's app-owned `helix.ui.edit_number`; PA and thousandth-step fields use
the bounded owned precise editor because the app editor supports at most two
decimals. Temperature Step5 is read-only; Flow selects Recommended/Perfectionist
and a native Orca surface pattern; PA has deliberate Direct Drive/Bowden defaults.
Drafts survive reopen and offer updates; Generate copies scalars into the immutable
request, including for known blocked capabilities so the actual coordinator retains
numbers and reports its real blocker. Missing context blocks locally. See
`docs/V1_NATIVE_PARAMETERS.md` for this functional correction and pending focused
independent800×480 operator/real-Coordinator proof. Historical396-frame fixture
proof does not qualify the changed controls.

The current native capture tool uses exact beta.12 source
`00a9fe6030c37d56748b2122b41fd36de1fdf831`, its hash-verified official desktop
archive for runtime/install compatibility, and the separately hash-verified
developer Actions binary for beta.12's control socket. Those binaries are not
interchangeable: the release binary has no test-control dispatch. The Actions
artifact is only an accelerator; `helix-beta12-qualify.py bootstrap --refresh
--from-source` clones the exact commit, verifies all 14 recursive submodule
revisions and builds with the pinned Ubuntu recipe after the artifact expires.
Cache metadata identifies the binary origin and never labels a source build with
either prebuilt digest. Capture runs use Docker `--test --network none`,
read-only plugin/runtime mounts and private native pointer controls. Every offered
context, generation result, parity disposition and print/completion status in
that capture is an explicitly synthetic fixture. It qualifies UI behavior only;
it is not generator parity, Windows qualification, printing or hardware evidence.

## Accepted native fidelity

The home tile is the accepted Temperature compact layout byte-for-byte, with
only its status subject rebound to V1. The builder verifies that accepted source
hash and the derived copy. Icon, two-line identity, muted status and tap-to-open
remain unchanged. The manifest declares **1×1 logical cells**. HelixScreen
stores two tracks per cell, so a saved `2×2` track span is already logical `1×1`;
the earlier checkpoint must not be described as a logical 2×2 tile. The qualifier
now omits saved span overrides, asks the host to use the manifest defaults, and
asserts the native home API reports `w=1,h=1`. Every icon/identity/status child
must fit inside that tile and their vertical bounds must not overlap.

Flow Ratio uses the fixed Recommended (`pass:1`) or Perfectionist (`pass:2`)
additive sample sets and exposes the frozen Orca-native Archimedean Chords or
Monotonic pattern choice. These controls do not write an Orca profile.

All five calibrations use beta.12's documented queued `helix.ui.dialog()` result
picker. It waits behind app-owned warnings, lock and print-complete dialogs, then
appears without retiring the owned preparation view or covering the app surface.
Dismissal leaves the result manually reachable from the accepted tile/job flow.
The picker and embedded manual fallback share one immutable result handler. No
timer, notification preference or upstream patch is used.

A request/prepared/job/completion-bound automatic-attempt claim is recorded
before storage persistence and before opening. Failed persistence disarms the
attempt and locks actions. A dismissed or failed attempt is never retried
through duplicate status. The host defers writes, so restart always disarms
automatic presentation; a restored completion with a missing claim receives a
conservative `recovery-suppressed` claim. Fresh exact coordinator completion must
re-verify pending choices before manual reopening. A committed result stays
immutable. Pending/applying preset transactions restore as failed/needs-recheck,
never as success and never as an automatic retry.

The historical qualifier/capture added native checks for logical compact bounds,
the historical beta.9 automatic Temperature presentation on Home/Print Status/Controls, preserved
native dismissal, duplicate suppression, manual reopening, restart and a lost
claim. Recovery restarts only the exact existing ManagedRun-owned synthetic
container; it creates no replacement container and preserves the retained state.
All inputs remain synthetic and network-none. Existing workflow frames are kept,
with five explicit Confirmed/Start frames added: **36 frames per viewport, 396
across all eleven targets**. Those captures remain historical and are not
relabeled. The beta.12 qualifier requires **39 frames per viewport**, adding a
queued warning and application failure/applied states. Raw tile
geometry and presentation transitions are also retained in each private capture.
Those completed 396-frame sources remain historical; the current parameter
correction uses the focused800×480 gate authorized in
`docs/V1_PARAMETER_CORRECTION.md`, without relabeling the old fixture evidence.
No capture, build, physical action or deployment was performed for this source
correction while the shared heavy-work slot was owned elsewhere.

## Restart status reconciliation

A retained session without a committed result restores as `uncertain`, with its
sequence and exact original request/prepared/job/completion bindings retained and
`recovery_required: true` persisted. All actions and evaluation remain locked.
Lua continues to reject every status whose sequence is equal to or older than
its retained sequence. The coordinator's `reconcile_native()` checks that marker,
request and retained bindings, then durably republishes the authoritative phase
with a newer sequence when the reader is exactly current. An already older
reader receives current status without another bump. Repeated markers cannot
advance the journal repeatedly and reconciliation dispatches no action.

Only a fully validated newer status clears the native marker. A recovered
Confirmed status additionally requires the retained exact Confirm intent; it
never invents confirmation or repeats Start. A recovered Complete status requires
the same prepared job and independent completion digest, and restores evaluation
manually without another automatic result dialog. Committed results and
receipts stay immutable. Blocked, Failed and Cancelled are safe terminal states
and remain terminal on restore, so a runtime that has archived them does not
strand the chooser in an unnecessary recovery wait.

The qualifier now generates deterministic Review, Confirmed and Complete restart
cases by driving actual `Coordinator.request()`, Confirm/Start intents and
independently matched job observations, then calls the actual reconciler. A real
small synthetic artifact is written and reverified; parity verification and the
physical job adapter are explicitly synthetic UI boundaries. Each native case
first receives the real unchanged status and must stay locked, then receives the
real durable republish and must recover. Mismatched retained tokens, duplicate
and older status must not alter it. A second actual Complete restart checks a
retained suppression claim; the first checks a lost claim. These recovery cases
never derive freshness from the native session's sequence or the ordinary mock
status helper. The fixture inventory includes the exact coordinator source hash.
Python tests check these real transitions and deterministic fixture bytes; native
Lua execution still requires the new complete managed capture before promotion.

## Compact-screen product audit corrections

Parameter ranges use the native-font-safe word **to**. The evaluation heading,
explanation, picker and Return button each bind to the same hidden-until-complete
state. They remain direct children of the accepted native scroll area: a nested
non-scrollable wrapper prevents native scroll-to-view from reaching Return on the
smallest screen. Exact successful completion enables selection. Failed and Cancelled retain their
terminal outcome without evaluation or an Active tile label. The monitor no
longer claims printing is unavailable unconditionally: a disabled Start is
reported by the coordinator's actual blocker.

A Use-in-Orca click replaces the explicitly operated owned view with a compact
result view showing pending, applying, failed/retry, or applied/unsaved. Only an
exact v2 application event with `dirty=true` and `unsaved=true` may display
Applied. A legacy v1 ACK remains explicitly NOT APPLIED. ACK/application changes
subjects and never opens a surface over an unrelated native page. Manual Resume
can reopen the immutable result. No unsupported visibility API or timer is used.

Cancel uses beta.12's queued `helix.ui.confirm` warning surface. Dismiss/Cancel
keeps printing; only the explicit **Cancel print** callback persists the owned
cancellation intent. Nothing dispatches cancellation before that confirmation.
Structured Orca warnings use a separate queued plugin dialog so backdrop dismiss
does not masquerade as either Continue or Cancel. The retained native v2 decision
binds the exact request, Prepared digest and warning codes for coordinator pickup.

Status may carry nullable display-only `monitor: {elapsed_s, progress}`. Native
accepts finite elapsed seconds from 0 through 2,678,400 (31 days) and progress
from 0 through 1; malformed fields are rejected. Each field is displayed
independently, for example `25% · 2m elapsed`, `25% · Elapsed unavailable`, or
`Progress unavailable · 2m elapsed`. Both missing displays Progress unavailable.
Retained telemetry is cleared on restart. No elapsed/progress value, including
100%, can enable Confirm, Start, cancellation, evaluation or result return;
these still require their existing exact lifecycle and completion proof.

The failed portrait tile check was caused by the synthetic seed's inherited
`grid: 12x8` landscape stamp. The pinned host's `PanelWidgetConfig::switch_to_grid`
reprojects positioned entries to a different measured grid; this stretched the
1×1 logical tile to 1×2 on the 272×480 target. A new V1 test layout now omits the
stamp and parked grids and requests native auto-placement (`col=row=-1`), so
native adopts its actual grid without reprojection. The native load guard rejects
positioned coordinates without a grid stamp; leaving old `0,0` coordinates would
reset the whole synthetic layout to defaults rather than place the plugin.
Manifest 1×1, accepted tile bytes, actual home span and every child/nonoverlap
assertion remain mandatory. Bounds are recorded even when the assertion fails.
No existing user, printer, accepted or physical layout is migrated or changed.

The qualifier adds source-bound Confirmed/Start screenshots for all five
calibrations, nullable/malformed monitor cases, 100%-progress evaluation lock,
terminal evaluation visibility, readable Return/receipt/Done, and receipt arrival
while Controls remains visible. The beta.12 portable verifier requires the exact
shared 39-frame inventory for every target; older 341/396-frame checkpoints remain bound
to their historical source and do not establish these new behaviors. A fresh
complete eleven-size managed capture remains required before promotion.

Chooser/configuration cards bind separately to the latest validated Orca offer;
job/result cards keep the immutable session's original profile identity. A fresh
offer after a returned/blocked session cannot mislabel the next configuration or
replace its earlier result. The native fixture explicitly changes the next
printer display and verifies the retained original result stays unchanged.
