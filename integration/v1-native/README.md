# Native V1 derivative

This Build Program #14 derivative keeps the accepted `orcacal` identity, native
Helix home tile, overlay/header/Back navigation and responsive token language.
It adds five calibration configuration views, a prepared-job review with separate
Confirm and Start actions, progress, bounded evaluation and original-Orca return.
It never modifies or deploys the accepted Temperature plugin or physical install.

Build with `python3 scripts/v1-native-plugin.py --output <new cache directory>`.
The builder verifies the exact accepted shell source hashes and refuses existing,
symlinked or repository destinations. Runtime output defaults to the user cache;
captures default to XDG state. Only storage is requested. No native networking,
process, print RPC or profile mutation exists. The V1 coordinator remains the
trusted verifier of generator parity, expiry and exact independent completion.
Physical Start has no action adapter in this candidate. Native Start only stores
an exact preparation-bound one-shot intent after a prior Confirm round trip.

The common `docs/V1_CONTRACT.md` beta.9 adaptation is required: offers provide
runtime-generated request nonce/timestamps; statuses provide prepared digest,
completion digest and bounded evaluation choices; ACK includes the full committed
result and its digest. Beta.9 has no supported clock/hash API. Native structurally
compares immutable identity, parameters, job and result; it does not claim to hash
or enforce wall-clock expiration. The coordinator owns these checks. Restart
locks all unverified actions; a retained selection stays immutable until the exact
originating receipt. No event alone authorizes a physical action.

`catalog.json` contains offered native parameter dropdown values and labels,
including the shared defaults. Values outside this bounded UI envelope remain
unsupported by this derivative. Availability means generation can be attempted;
it never means parity qualified. Blocked generators explain their reason and
cannot expose Confirm/Start. The UI has no user-entered hash, receipt or technical
qualification requirement.

The native capture tool uses pinned beta.9, Docker `--test --network none`,
read-only plugin/runtime mounts and private native pointer controls. Every offered
context, generation result, parity disposition and print/completion status in
that capture is an explicitly synthetic fixture. It qualifies UI behavior only;
it is not generator parity, Windows qualification, printing or hardware evidence.

## Accepted native fidelity

The home tile is the accepted Temperature compact layout byte-for-byte, with
only its status subject rebound to V1. The builder verifies that accepted source
hash and the derived copy. Icon, two-line identity, muted status and tap-to-open
remain unchanged. The manifest declares **1×1 logical cells**. Pinned beta.9
stores two tracks per cell, so a saved `2×2` track span is already logical `1×1`;
the earlier checkpoint must not be described as a logical 2×2 tile. The qualifier
now omits saved span overrides, asks the host to use the manifest defaults, and
asserts the native home API reports `w=1,h=1`. Every icon/identity/status child
must fit inside that tile and their vertical bounds must not overlap.

Flow Ratio explains **YOLO (recommended)** and Orca's **Archimedean Chords**
surface. The one-choice implementation-only pass dropdown is removed. The
request contract still retains `pass: 1` internally; no new generator API or
parameter is introduced.

Temperature preserves the accepted immediate automatic result presentation,
through the documented beta.9 `helix.ui.overlay()` adapter. A distinct owned
result component avoids the host's no-op when a manual job view is buried. It
shares the same subjects, selection locks and immutable original-context return
handler as the manual view. Only the plugin's preparation views retire; native
Print Status, Controls and unrelated native dialogs remain. The accepted
immediate-overlay behavior can overlap a native dialog. It remains **Temperature
only**; the other four calibrations refresh an already open job view and keep
pending results manually reachable. No queued-modal API, timer, notification
preference or upstream change is assumed.

A request/prepared/job/completion-bound automatic-attempt claim is recorded
before storage persistence and before opening. Failed persistence disarms the
attempt and locks actions. A dismissed or failed attempt is never retried
through duplicate status. The host defers writes, so restart always disarms
automatic presentation; a restored completion with a missing claim receives a
conservative `recovery-suppressed` claim. Fresh exact coordinator completion must
re-verify pending choices before manual reopening. A committed result and its
originating receipt stay immutable and NOT APPLIED across recovery. The isolated
`presentation.lua` adapter can adopt a future supported queued API without
changing these completion/result rules.

The revised qualifier adds planned native checks for logical compact bounds,
automatic Temperature presentation on Home/Print Status/Controls, preserved
native dismissal, duplicate suppression, manual reopening, restart and a lost
claim. Recovery restarts only the exact existing ManagedRun-owned synthetic
container; it creates no replacement container and preserves the retained state.
All inputs remain synthetic and network-none. Existing 31-frame names are kept,
with the Temperature evaluation frame showing the automatic view. Raw tile
geometry and presentation transitions are also retained in each private capture.
These source changes require a new complete eleven-size capture before promotion;
the prior 341-frame checkpoint remains evidence of its exact earlier source.
No capture, build, physical action or deployment was performed for this source
correction while the shared heavy-work slot was owned elsewhere.
